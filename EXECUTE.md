## 🔄 Operational Cycle  

### **1 — Load Proposals**  
EXECUTE reads incoming proposals from:  
`IPC_DATA/proposals.json`

Each proposal includes:  
* Action type  
* Target path  
* Safety level  
* Required confirmations (`PanelAPI` [ÁNO/NIE])  
* Execution metadata  

### **2 — Validate Proposal**  
* Confirm action type  
* Check file existence  
* Verify safety level  
* Reject destructive or unconfirmed operations  
* Enforce **REPORT_ONLY** for duplicates  

### **3 — Execute Action**  
Supported operations:  
* File creation  
* File modification  
* File duplication  
* Safe deletion (non‑critical only)  
* System‑level tasks (only with explicit confirmation via `PanelAPI`)

All actions follow deterministic rules and cannot modify autonomy logic.

### **4 — Generate Response**  
Results are written to:  
`IPC_DATA/responses.json`

Each response contains:  
* Status (success / fail / report_only)  
* Action performed  
* Target path  
* Metadata  
* Safety notes  

### **5 — Cleanup**  
Temporary buffers are cleared and EXECUTE prepares for the next cycle under Guard runtime supervision.
